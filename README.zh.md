**智能体在等你、或干完活时，轻轻响一声。**

人不在窗口前也不怕：后台弹系统通知（**点击即回到窗口**），任务栏标题亮出「待处理 / 已完成」；你回来看过一眼之后，它就闭嘴——不会像闹钟一样反复催你。

**安装**：DSH → 设置 → 插件 → 添加插件，粘贴下面这行，点「安装」：

```
dsh-plugin-notify-sounds
```

---

## 🎨 与 DSH 界面风格统一

设置面板中的每一处视觉细节都取自 DSH 自身的设计体系：行几何、分隔线、字号与间距沿用官方设计令牌，音效选择器使用官方 `Menu` 组件，图标来自官方图标族，排布沿用「文字左 / 控件右」的原生行式。安装后不会在设置中出现风格割裂的第三方区块。

## ✨ 它能做什么

| 提醒什么 | 效果 |
|---|---|
| **需要你决策** | 智能体发起审批、计划确认、提问时提示音；审批与提问可分别设音效 |
| **任务完成** | 会话由运行转为空闲时提示音 |
| **人不在窗口前也能感知** | 后台弹系统通知（正文就是审批理由或提问原文，点击回到窗口）；任务栏标题显示「待处理 / 已完成」 |
| **没看到会再提醒** | 未处理决策按 1/5/15/30 分钟重复提醒 |
| **只提醒你关心的** | 子智能体（后台任务）默认完全静默，只提醒主对话，可开关 |
| **该安静时安静** | 静音时段（如 22:00–08:00，可跨午夜）、仅页面不可见时提示、总开关一键全静音 |
| **声音随你** | 九种内置音效、自定义铃声上传、音量调节，每项独立开关 |
| **检测更新** | 设置里检查 npm 新版本，并指向真正负责安装的入口——设置 → 插件（卸载后再装）、市场，或 web profile 上的 `dsh plugin add`；若当前安装未被 lockfile 记录，会在行内提示 |

## 💡 为什么需要它

DSH 的状态提示只有视觉——状态点、侧栏标记。你一切到别的窗口，就既看不到也听不到，智能体却可能正卡在那里等你一句话。

这个插件把「在等你」和「干完了」变成声音。配合系统通知与标题标记，人走开也知道发生了什么；而你回来处理过之后它就安静——重复提醒也只针对你**从没看过**的决策。

## 🔔 声音

双音铃 · 风铃 · 单音叮 · 水滴 · 脉冲 · 上行琶音 · 金币 · 达成 · 敲门 —— 九种内置音效全部由 Web Audio 现场合成，不含任何音频文件、不发一次网络请求。

也可以换上你自己的铃声（mp3/wav/ogg，≤512KB，自动校验并做音量归一化），或者干脆选「无声」只留通知。三种触发（审批 / 提问 / 完成）各选各的音效，设置里随时试听。

## ⚙️ 设置

设置 → **提示音**（位于「通用设置」与「模型」之间），每项功能都有独立开关，界面与 DSH 原生设置完全一致：

总开关与音量 · 三种触发各自的音效（含试听）· 子智能体提醒 · 系统通知 · 窗口标题提醒 · 重复提醒间隔 · 静音时段 · 仅后台提示 · 自定义铃声上传 · 自动检查更新（安装走包管理器）

改动即时生效，无需重启。

## 📦 安装

### 🖱️ 最简单：在 DSH 里点两下（推荐）

1. 打开 DSH → **设置 → 插件**，点**添加插件**；
2. 在输入框粘贴包名（本插件已发布在 [npm](https://www.npmjs.com/package/dsh-plugin-notify-sounds)）：

   ```
   dsh-plugin-notify-sounds
   ```

   （填 GitHub 仓库地址 `https://github.com/BillCx330/dsh-plugin-notify-sounds` 或本地目录路径也可以）
3. 点**安装**，装完**重启 DSH** 一次。

输入框上方的「安装源」是下载源，默认中国大陆镜像源，国内一般不用改。DSH 会提示「插件以你的权限运行」——本插件只读会话状态、在本地发声；唯一的请求是点击系统通知时发给**本机 DSH** 的唤窗请求，不向外部发送任何数据。

### ⬆️ 升级

**升级由包管理器安装**，这样 profile 的 lockfile 会跟着一起更新——DSH 插件无法自己持久地更新自己（管理器拒绝已声明的包，而它的「先移除再安装」会先卸载掉正要完成安装的代码）。所以插件只负责**检查**，并告诉你从哪里装：

- **在 DSH 里（推荐）**：设置 → 插件 → 卸载本插件 → **添加插件** → 粘贴 `dsh-plugin-notify-sounds@<版本>` → 安装 → 重启 DSH。（建议带版本号：pnpm 的 `minimumReleaseAge` 策略会让刚发布的版本暂时不参与自动解析，只写包名可能装到上一个版本。）
- **装了市场插件**（[dshmarket](https://www.npmjs.com/package/dshmarket)）：在市场里一键更新。
- **`web` profile**：`dsh plugin --profile <你的 profile> add dsh-plugin-notify-sounds@<版本>`。

更新行还会提示「当前版本与 lockfile 记录不一致」——那是 1.8.0 之前的自更新留下的状态，按上面方式重装一次即可永久修好。

### 🛠️ 其他安装方式

**命令行** —— 对你实际使用的 profile 一条命令：

```sh
dsh plugin --profile <你的 profile> add github:BillCx330/dsh-plugin-notify-sounds
```

**Release 压缩包** —— 从 [Releases](https://github.com/BillCx330/dsh-plugin-notify-sounds/releases) 下载 `.tgz`，用它**在磁盘上的路径**安装：

```sh
dsh plugin --profile <你的 profile> add ./dsh-plugin-notify-sounds-1.8.4.tgz
```

（`dsh plugin add` 把参数原样交给包管理器，所以要给本地文件路径，不能填下载地址。）

**本地目录** —— 开发或试用未发布的改动：

```sh
dsh plugin --profile <你的 profile> add ./dsh-plugin-notify-sounds
```

**手工编辑** —— 在 profile 的 `package.json` 的 `dependencies` 加 `"dsh-plugin-notify-sounds": "github:BillCx330/dsh-plugin-notify-sounds"`，在 `dsh.profile.bundles` 追加 `"dsh-plugin-notify-sounds"`，然后在 profile 目录跑一次包安装（如 `pnpm install`）把依赖装进 `node_modules`。

命令行方式会自动写入 `dsh.profile.bundles` 并装好依赖，无需手工编辑。包内直接带预构建产物、不声明任何生命周期脚本，安装过程不执行构建脚本。安装后**重启 DSH**（日常升级仅客户端改动时，可热更生效）。

## ⚠️ 已知边界

- **手改配置**：偏好写在 profile 的 `cordis.patch.yml`，值必须符合 schema（音量 0–100、音效为预设之一、时间 `HH:MM`）；写错会让插件不加载，改回即可。设置界面只会写入合法值。
- **升级由包管理器安装，不再由插件自己完成**：1.8.0 移除了自安装器（原地写文件从不会更新 profile 的 lockfile，于是下一次插件安装会静默把旧版本装回来）。更新行仍会检查 npm、报告新版，然后指向真正负责安装的入口——设置 → 插件（卸载后再装）、市场，或 web profile 上的 `dsh plugin add`。
- **1.7.0 及更早版本**可以通过它们自带的自更新到达 1.8.0（1.8.0 保持同样的七个文件名），但这次到达不会被 pnpm 登记：按上面的方式用包管理器重装一次，此后所有升级都会留下。1.6.9 及更早无法安装「新增了文件」的版本——固定白名单会安全拒绝；同样的一次性重装即可解决。
- **多窗口**：各窗口独立触发，同一事件可能各响一次；打开「仅在页面不可见时提示」即可避免。
- **点击通知回到窗口**：Windows 完整实现并实测；macOS / Linux 走系统深链，未验证。
- **唤窗按窗口标题定位主窗口**：刻意不读取其他进程信息（那会触发杀软主动防御）。若将来 DSH 改变标题格式，唤窗会静默失效——提示音与通知本身不受影响。
- **导航小图标**：依赖设置面板的 DOM 结构，若DSH 改版后自动回落为官方齿轮，仅影响外观。
- **通知权限**：桌面端放行；受限环境（某些浏览器策略）下被拒时，行内会引导手动允许，其余功能不受影响。
- **macOS 的系统通知**：桌面外壳对权限请求一律放行，所以设置里恒显示「已授权」；**实际是否弹横幅由 macOS 决定**（系统设置 → 通知 → DeepSeek Harness），未签名的开发版可能静默失败——「显示已授权却没通知」多半不是插件的问题。

## 🧩 设计与实现

给想改代码的人看的要点（实现细节以源码注释为准）：

- **触发不碰事件瀑布**：审批/提问的请求是 waterfall 事件，UI 应答后晚注册的监听器收不到。本插件改读 `uiSession.sessionStatus`（DSH 自己聚合的 pending/running 事实，与侧栏状态点同源），纯观察、零侵入。
- **重复提醒的节拍**：15 秒粒度检查未处理决策；**看过即除名**（决策出现时你正在窗口、或之后回到窗口，都算看过），切走不重新武装；新问题替换旧问题会重置计时。免打扰期间的提醒直接作废，不会顺延到时段结束补发。
- **通知点击回到窗口**：渲染进程唤不起 OS 窗口，点击时 POST 到宿主半边的 `/notify-sounds/focus`（带 connection 围栏），由宿主唤起。Windows 用 DSH 自带的 `koffi` 直接调 `user32.dll`（不引新依赖、只操作窗口、不启动 PowerShell——那会触发杀软主动防御并归因到 DSH）；桌面端/浏览器端按 `Origin` 头自动区分，浏览器端不误唤桌面窗口。
- **通知折叠**：不把 `tag` 交给平台（平台替换旧通知时会吞掉指向它的点击），由插件自己关旧发新，并持有每一代通知对象的引用，避免点击回调被回收成死按钮。
- **标题标记**：只做前缀加/删，与 DSH 自身的标题管理互不干扰；前缀按实际写入的文字记录，语言切换不叠加、不残留。「已完成」是未读消息——离开期间发生的完成才标记，回到页面即清除——不是常驻的「空闲」状态，看过的完成不会在每次切走时重新出现。
- **免打扰即遗忘**：静音时段内发生的决策与完成不记账——不响、不通知、不打标题标记，时段结束也不补发；本该在时段内发出的重复提醒直接作废。
- **冷却与健壮性**：同一会话的同类触发 2 秒内不重复响（另一个会话的决策照常响）；音量经 `Number.isFinite` 防护（手改 YAML 的非法值回落默认）；写入被拒时控件回弹到已接受值并显示错误行；开关写入中禁用，防双击竞写。
- **音量滑杆**：非受控输入，拖动只写 CSS 自定义属性，松手才提交一次，不卡顿、不回弹。
- **主题与排版**：全部使用 `--dsw-alias-*` 令牌，分区与行几何复刻官方设置页；音效选择用官方 `Menu` 下拉，不会撑出横向滚动。

## 📜 更新记录

- **v1.8.5**（2026-10-20）**文案跟上机制。** 更新行此前仍写着「发现新版可一键安装」——从 1.8.0 起已不支持：这一行只负责检查，并指向包管理器。现在行内如实说明，且引导里带上版本号（`dsh-plugin-notify-sounds@{version}`），避免刚发布的版本被 pnpm 的 `minimumReleaseAge` 策略静默解析成上一个版本。README 的功能表、设置摘要与安装步骤不再承诺一键安装；历史更新记录保持原样。
- **v1.8.4**（2026-10-20）**点击通知一定能找到窗口。** 真实点击的日志显示：窗口明明存在，原生唤窗却报 "no window found"——隐藏或正在重绘的窗口可能瞬时返回空标题，而当时的搜索只认标题。现在窗口搜索同时按「拥有窗口的进程」匹配（桌面壳是本宿主进程的父进程），前台请求连续重试三次之后才走深链兜底。
- **v1.8.3**（2026-10-20）**窗口关到托盘时，点击通知也能回到 DSH 了。** 原先的 Win32 唤窗只搜**可见**窗口，关到托盘的 DSH 窗口永远找不到，只能退到很慢的深链兜底——表现就是「点了通知没反应」。现在会记住标题匹配的不可见窗口，并在置前之前先 `SW_SHOW` 让它显示出来；深链仍作为最后兜底。
- **v1.8.2**（2026-10-20）**真正修好目标模式的提醒。** 1.8.1 的宿主路由读了 `stateOf(session, "goal")`，却取 `current.phase`，而投影值把 goal 嵌在里面：`current.goal.phase`。于是每次读取都为空、每轮照响。现在改为读嵌套字段（并保留扁平形状的兜底），宿主侧调试记录已确认：中间轮 `current.goal.phase` 是 `active`，最后一轮是 `complete`。
- **v1.8.1**（2026-10-20）**修复目标模式的提醒。** 1.8.0 的开关从浏览器自己的会话投影读 phase，而那份投影只包含这个页面打开过的会话——目标所在的会话没被打开过时读到空值，代码把它当成「没有目标」，于是每轮又照响。浏览器半现在改问宿主新增的只读路由 `/notify-sounds/goal`（宿主的投影存储才是权威的），并在目标仍为 `active` 时持续复查：目标完成、暂停或受阻时响唯一一次；会话重新开始运行则保持安静。宿主不回答该路由时退回旧行为。
- **v1.8.0**（2026-10-20）**插件不再自己安装更新，改由包管理器负责。** 原地写文件从不会更新 profile 的 lockfile，于是下一次插件安装（或市场升级）会静默把 pnpm 记录的版本装回来：1.7.0 的安装可能一声不响退回 1.6.9。DSH 0.2.1 让插件无法从内部持久地自安装（管理器拒绝已声明的包，而它的「先移除再安装」会先卸载掉正要完成安装的代码），所以自安装器被移除：更新行只检查 npm、报告新版，并指向真正负责安装的入口——设置 → 插件（卸载后再装）、市场，或 web profile 上的 `dsh plugin add`。它还会把「运行版本」与「lockfile 会恢复的版本」做比较，**不一致时明确提示**，把静默回退变成用户可自助修复的状态。**新增：目标模式下等目标结束再提醒**（issue #2）——目标模式会自动进行多轮，原先每轮结束都会响；新开关「目标模式下只在最终轮提醒」让中间轮保持安静，只在目标完成、暂停或受阻时响一次（普通对话不受影响；默认关闭）。本版保持同样的七个文件名，1.6.9 / 1.7.0 的安装仍可通过它们自带的自更新到达 1.8.0——之后用包管理器重装一次，升级即永久生效。
- **v1.7.0**（2026-10-16）**更新机制的转折点**：一键更新不再受「固定七个文件名」的白名单约束，改为按规则接受包目录下的任何普通文件——路径穿越、绝对路径、符号链接、非普通文件、保留名字（更新器自己的备份/临时名与记录文件、`.git`、`node_modules`、`.npmrc`）、含 `:` 的路径段，以及只有大小写不同的重名或**与 `package.json` 声明的入口只差大小写**的文件，依然一律拒绝，文件数与解压体积也都有上限（解压时即受 `gunzip` 上限约束）。**1.7.0 及以后可以正常更新到任意增减文件的新版**：某个版本去掉的文件现在会真的被删掉（依据更新器自己留下的 `.update-manifest.json` 记录，**只删它自己装过的文件**，用户放进目录里的东西一律不动；第一条记录之前的安装不做任何猜测）。**1.6.9 及更早**遇到「新增了文件」的新版会更新失败（安全失败：一个字节都不写，已装版本继续正常工作），README 里说明了重装一次的办法。修复：关掉「自动检查更新」会让每日轮询永久停摆（重新打开也不恢复）；窗口标题在两次 Win32 读取之间变短时，点通知唤窗会静默失效；预发布版本号按字符串比较（`rc.10` 被误判为比 `rc.9` 旧）；**同一个 GUI 开多个标签页或多个窗口时提示音、系统通知、重复提醒全部翻倍**（现在由 BroadcastChannel + 本地记录选出一个「发声页」，其余页保持安静，只在发声页消失后接管；窗口标题标记各窗口独立，不受影响）；自定义音效的峰值归一化改为**逐样本**扫描（原先每 8 帧抽样会与接近 fs/8 的高频混叠、系统性低估峰值）。更新失败时给出**按阶段区分的建议**（网络类提示重试；解包/替换类给出手动重装步骤与仓库地址，并列出失败的两个版本号），写入顺序改为**最后写 `package.json`**（中途崩溃时检查仍会提示更新，用户再点一次即可自愈），并会校验归档里的清单确实是本包、确实是 registry 报的那个版本。设置里「自定义音效」移到**三种提示音之后**（它们才是会用到它的三处）；`settings` 相关的小修：冷却表改为真正的 LRU（原先是 FIFO，最常触发的会话反而最先被淘汰）、会话列表每轮只取一次快照、macOS 桌面版的「窗口标题提醒」开关改为**禁用**（原先能打开但标记无处显示）、英文界面更新提示里残留的全角标点修掉、README 的 Release 安装说明改为可照做的本地路径写法。

## 💻 开发

```powershell
npm install             # 一次性：宿主测试需要 schemastery 开发依赖
node test/smoke.mjs     # 客户端半：装配、触发、冷却、静音、重复提醒、通知点击、子智能体过滤
node test/host.mjs      # 宿主半：配置 schema、唤窗路由、标题匹配、两半契约交叉校验
```

发布到 npm：升好版本号后 `npm publish`（首次发布先 `npm login` 并按提示开启 2FA）。**npm 的版本号不可覆盖**——有任何改动都请升版本再发。

```
dsh-plugin-notify-sounds/
├── package.json        # dsh.bundle.patch + dsh.client
├── cordis.patch.yml    # Loader 行：id: notify-sounds
├── lib/
│   ├── index.js        # Host 半：配置模式 + 点通知唤窗路由
│   └── client.js       # Client 半：音效引擎、状态监听、设置分区
└── test/
    ├── smoke.mjs       # 客户端半
    └── host.mjs        # 宿主半
```

`package.json` 已按可发布形态声明（`files` 只带运行时产物，`@deepseek-ai/schemastery` 为 peerDependency、另有一份 devDependency 供宿主测试，纯 ESM、无构建步骤），日后发 npm 直接 `npm publish` 即可。
